# Proof of concept

::: warning Not a running service
The proof of concept runs on a developer machine and in CI. No Calistar service is hosted, and no project is enrolled. It exists to check the design before it is built.
:::

It is in the [repository](https://github.com/Calistar-io/calistar), and anyone can run it: the steps are in the repository's README. Every result below comes from tests that also run in the repository's CI, on a hosted runner with Docker.

## What it contains

| Part | Where | State |
| --- | --- | --- |
| Local stack: PostgreSQL, Umami 3.5.0, OpenTelemetry Collector 0.165.0, gateway, reverse proxy | `infra/compose`, `infra/collector` | Images pinned by digest. One command starts it. Only the reverse proxy is published. |
| Gateway | `apps/gateway` | API path and web path. No bot checks beyond Umami's, no origin check, no rate limit yet. |
| Reverse proxy | `infra/compose/proxy` | An allow-list: ingestion to the gateway, and of Umami only what a read-only dashboard needs. |
| Path normalizer | `packages/normalizer` | The ordered rules, with a corpus generated by the Stellar SDK. |
| Example API | `examples/otel-node` | A Node.js service instrumented with the OpenTelemetry SDK. |
| Example site | `examples/static-html` | A static page that loads the tracker. |
| Stack tests | `tests/e2e` | 44 tests, run against the stack, with a real browser where one is needed. |
| Load script | `tests/load` | A short run on the API path, with a check that what is stored equals what was sent. |

Left out on purpose: the console and enrollment, the reduced tracker build (the example site uses Umami's stock script, served through the gateway), the bot and inflation layers, daily rollups, row-level security, the Metrics API, infrastructure as code.

## What the tests show

### Path normalizer

280 unit tests. The corpus holds every key type the Stellar SDK (17.4.0) can encode, and the test suite fails if the SDK gains a type the corpus does not cover.

- An account, a contract, a muxed account or any other Stellar key in a path becomes a placeholder: `/accounts/G…/payments` is stored as `/accounts/:account/payments`.
- A secret seed is redacted wherever it sits in a segment: alone, glued to other text, in lower case, or percent-encoded several times.
- UUIDs, hashes, hex values, integers and opaque tokens become placeholders too. An ordinary word is left alone.

### API analytics

10 tests on the running stack, through the real Collector.

- **Traces and logs leave nothing.** A unique marker is sent in a span name, a span attribute, a log body, a log attribute, a request path and a metric attribute outside the schema. Afterwards one aggregate row exists, every other table of both databases has the same row count as before, and the marker is absent from a dump of both databases and from the logs of every service.
- **A data point belongs to the token's tenant.** A tenant named in the payload, in the resource or in a request header is ignored. A data point that names the tenant twice is refused.
- **A cumulative stream is converted without double counting**, and two tenants sending the same stream do not share state.
- A request without a valid ingest token is refused.

### Web analytics

5 tests on the running stack, with a real browser loading the example site.

- The page view is counted by Umami for that website. A second view by the same visitor is a page view, not a new visitor.
- The visitor's address is in no table and no log. The query string, the page title and the language are not stored either, although the stock tracker sends them: the gateway removes them.
- The page sets no cookie and writes nothing to `localStorage` or `sessionStorage`.
- An address, a user agent or a salt supplied in the event is ignored. Custom events and identification are refused.
- A browser that announces itself as automated is not counted.

### Provisioning and single sign-on

12 tests on the running stack.

- A team, a website and a read-only user are created through Umami's API. The user is signed in on the server side, and a browser opens that user's dashboard through Umami's `/sso` page, with no sign-in form.
- The user can read its website and its numbers. It cannot edit, reset or delete the website, cannot create a website, a team or a user, and cannot change its role, its username or its password.
- It cannot read another tenant's website.
- A token stops working when the user's password is rotated.

### Reverse proxy

17 tests on the running stack. The proxy is the only thing the stack publishes.

- Ingestion works through it, and a caller cannot choose the address the gateway sees: the gateway takes the address the proxy wrote, whatever `X-Forwarded-For` header the caller sent.
- The dashboard works through it: a browser opens it from a token, and every route it calls on the overview, events, sessions, realtime and compare pages is published.
- Umami's collection endpoints, its tracker script, its sign-in page and its sign-in route answer 404.
- Nothing that writes reaches Umami, even with a valid token: not the API-key route, not a rename, a reset or a deletion.

### Load

One short run, on the API path, on a GitHub-hosted runner. The stack and the load generator shared the machine.

| | |
| --- | --- |
| Duration | 10 minutes |
| Workload | 50 exporters, one export every 10 seconds each, 40 data points per export |
| Requests represented | 120,040, or 200 per second: 17 times the RFP design target of 1,000,000 per day |
| Exports refused | 0 |
| **Requests stored** | **120,040: equal to what was sent** |
| Ingest latency | median 2.2 ms, 95th percentile 3.4 ms, 99th percentile 4.9 ms |

This is ten minutes on one machine, not the one-hour test planned for the service. The script, the count check and the details of the run are in `tests/load`.

## Assumptions checked

The architecture document marked several points as assumptions. This is what was found, on the pinned versions.

| Assumption | Result | How it was checked |
| --- | --- | --- |
| Umami derives everything from an address the gateway controls | **Confirmed, with a condition.** Umami takes the address from the event itself when one is given, without any check. The gateway sets it to the truncated address. Umami must therefore never be reachable directly, or anyone could choose the address and the user agent. | Source, then a test |
| Umami stores no address | **Confirmed.** No table has an address column. | Source, then a dump searched for a marker address |
| The gateway's daily salt enters the visitor hash | **Confirmed.** Umami mixes the event's salt into its own, which rotates daily when told to. | Source |
| Only the country is derived from the address | **Disproved as configured.** The stock image ships a city-level database, and Umami stores region and city from the truncated address. Country-only storage needs a country-level database, which was not tested. | Observed on the stack |
| The Collector can stamp the tenant from request metadata | **Confirmed, with two corrections.** The stamp must come before the cumulative-to-delta step, or two tenants sending the same stream share state. And the Collector passes a repeated attribute key through, so the gateway refuses a data point that repeats one. | Tests |
| A cumulative stream that moves to another Collector is not counted twice | **Confirmed on one Collector** with the setting that treats the first point of a stream as a baseline. Its cost: the interval between the first two points of every new cumulative stream is not counted. Failover between two Collectors was not tested. | Test |
| Exponential histograms are handled | **They are dropped.** The Collector has a conversion function, which was not tested. Services must export explicit-bucket histograms, the SDK default. | Test |
| Umami's API can provision a team, a website and a read-only user | **Confirmed, with one correction:** a team's website is created through the websites route, not through the team's. | Tests |
| A token passed to `/sso` signs the browser in | **Confirmed.** The token has no expiry of its own. It stops working when the password changes, so rotation is what bounds its life. | Source, then tests |
| A read-only user cannot change or erase its numbers | **Confirmed for the website, with one gap in Umami, closed by the proxy.** The user can create an API key, and that key keeps working after a password rotation. Umami's sign-in route also stays reachable when its sign-in page is disabled. The reverse proxy publishes neither. | Tests |
| Umami can be published through a list of routes | **Confirmed.** The dashboard of a read-only user calls 14 read routes and one token check. The list was recorded from a browser session and is the proxy's allow-list. | Tests |
| Upstream component names | **Changed.** The Collector's processor and exporter are now `cumulative_to_delta` and `otlp_http`. The latest Collector release with a published image is 0.165.0. | Running the image |
| The Stellar key types to normalize | **One was missing:** muxed contracts (`W…`), present in the current SDK. Added. | The corpus test |

Not checked yet: failover between two Collectors, a country-level location database, and the two statements about GoatCounter in the base-project comparison.

## What the proof of concept changed in the design

Writing and reviewing the code turned up cases the design did not cover. Each is now a test.

- A secret seed glued to other text, in lower case, or percent-encoded more than once matched no rule. Stellar rules now run on the fully decoded, upper-cased segment, and a segment still encoded after 16 rounds is redacted.
- A data point with a repeated `tenant.id` could be stored under the tenant the caller chose.
- A malformed number in a data point could make PostgreSQL refuse a whole batch, which the Collector would then retry forever. Every number is validated first, totals are capped, and a point older than 24 hours or in the future is refused.

## Limits

- The tracker is Umami's stock script. It sends the page title, the language and the query string, which the gateway removes, and it reads one `localStorage` key. The reduced build removes both at the source.
- The gateway does not yet check that an event comes from a verified domain of its website.
- The proxy's allow-list covers the dashboard pages a test visits. A page it does not visit may call a route that is not published, and would then show an error.
- Region and city are stored, as explained above.
- The two tenants and their ingest tokens come from a seed file. There is no console.
- Umami's first-boot administrator password is not rotated by the stack.
